# go2lean v0.1.3

The week the LLVM line went from a prototype to something that finds
defects in real C libraries, and the first catalog property found on the Go
line from a spec written with no advisory behind it. The Go line also got a
symbolic executor, a conformance harness for QUIC, and a first check of
specs written from an RFC.

## Install

    go install github.com/fooexec/go2lean/cmd/go2lean@v0.1.3
    cd your/module && go2lean run ./...

Requires Git, Go 1.26 and elan (https://github.com/leanprover/elan). The
LLVM line (C) also needs LLVM's development files and a build with
the tag: `go build -tags llvm18 ./cmd/go2lean` (docs/usage.md).

## New this week

**The LLVM line** (`go2lean llvm`, `go2lean agent lib.c`):
- Specs in C: a function marked `annotate("go2lean:spec")` whose 0 is a
  violation; `go2lean agent` writes them for a C file.
- Inputs from the code's C types: a pointer to a struct is built member by
  member, a `char *` is a string, an `int *` is an out parameter.
- Modelled: the heap (use after free, double free), `string.h` and glibc
  `ctype`, `strtod`, `errno`, `ptrtoint`/`inttoptr`, and floats.
- `-memory`: memory errors only (out of bounds, use after free, double
  free); signed arithmetic wraps. A finding names its class.
- `-fuzz`: libFuzzer on what the model's search does not settle, under the
  sanitizers.
- `-lib`, `-cflags`: a library of several files.
- A CI job for the line and a golden regression of 35 functions.

**The Go line**:
- `go2lean symexec`: a bounded symbolic executor (Z3) for functions of integers
  and byte slices; it found all 12 panics of a benchmark that fuzzing and the
  search found 8 of (docs/eval/symexec.md).
- A property catalog (docs/specs/): redirect, CORS, client IP, static
  files, authorization matching, and path normalization.
- Initializers run in Go's order; `time` formatting is modelled; the
  refinement loop translates a forced function's callees.
- `go2lean zorya run|replay`: runs Zorya (concolic execution of a compiled
  program, Z3) and replays each reported input on the binary. On the symexec
  benchmark it reproduced 2 of the 5 functions it was tried on and gave
  inputs that do not panic for the other 3; it needs Ghidra, GDB and a Rust
  build (docs/eval/symexec.md).
- A pointer the model built (an allocation, a modelled call's result, a
  pointer loaded from an object the model owns) is no longer an opaque
  handle, so stores through it are kept; this removed two spurious verdicts
  on quic-go specs (docs/semantics.md). `a & ^b` is one `andNot`.
- `go2lean advisory` drafts a catalog property from a published advisory
  (OSV); a leave-one-out run on chi's `RedirectSlashes` advisories found the
  second from a spec drafted from the first (docs/eval/advisory-transfer.md).
  The 25 advisories of quinn, quiche, s2n-quic and Netty's HTTP/3 codec were
  turned into properties for quic-go (docs/specs/quic-*.md,
  docs/specs/http3-decoder-bounds.md); they held.
- The RFC rule-set method: a spec stated as the complete rule set of the
  RFC, independent of the package, finds a check the project has not added
  yet; it found the SETTINGS case below (docs/eval/quic-go.md).
- `examples/quic-conformance`: an attacking QUIC endpoint built from a copy
  of quic-go that sends the frames, packets and transport parameters of
  RFC 9000 sentences to an unmodified quic-go. 96 rules, 91 agree; the 5
  that differ are error codes of a MAY or an ambiguous case
  (docs/eval/quic-go.md).

**The proofs**:
- `go2lean prove`: shift lemmas, `wp_bounded` and large constants; all 17
  goals of `examples/proofs-limits` are proved, including the shape of
  quic-go's `DecodePacketNumber`. The RFC pilot (docs/eval/rfc-pilot.md)
  checked that function against a Lean statement of the RFC by running the
  model (154,112 exhaustive and 12,532 sampled inputs, no disagreement); the
  proof of that statement is not finished.
- The judge accepts a proof when only nanoda is ended by the out-of-memory
  killer and every other checker accepted; the certificate lists it in
  `unrun_checkers` (docs/trust.md). Any other fault is still a rejection.

## Findings

**73 defects in 30 projects**, 44 of them new (as of 2026-11-20); the list
with severities is docs/findings.md.

This week:
- **cJSON**: from one advisory each, the agent's specs re-found
  CVE-2024-31755, CVE-2023-50471 and CVE-2023-53154, each held from its fix
  on; the use after free of cJSON#1081 is still open upstream.
- **stb_image**: a GIF decoder read out of bounds (fixed on `dev`, not on
  `master`), and two undefined-behaviour cases, rated minor.
- **fasthttp**: `URI.Path()` is not idempotent, so a doubly-encoded dot
  segment becomes a traversal for a consumer that decodes again (low).
- **beego**: a guard filter is skipped with case-insensitive routing (high;
  reported privately).

- **quic-go**: four low, drafted and not filed: an empty `content-length`
  accepted and dropped, a CONNECT `:authority` without a port, a field value
  with surrounding whitespace passed on untrimmed, and a SETTINGS frame with
  a reserved HTTP/2 identifier accepted (docs/eval/quic-go.md).

Two small JSON parsers, json-parser and parson, came back clean: no
crash in tens of millions of fuzzer runs, and the model passes through
parson end to end.

## Known limits

- **A bounded search, not a proof:** no counterexample does not mean
  correct. The LLVM line's exhaustive engine covers small inputs only.
- **Not modelled on the LLVM line:** `sprintf` and `sscanf`, hexadecimal
  floats, threads, and most of libc beyond the list above.
- **Symbolic execution:** `symexec` takes integers, booleans and slices of
  integers; an `io.Reader`, a struct or a string makes a function
  unsupported, and it never says that a function cannot panic. Zorya reports
  an input per branch, so every report is replayed; `symexec` found
  nothing in the libraries it was run on (docs/eval/symexec.md).
- **The QUIC harness** covers what the table expresses with raw frames,
  packets and transport parameters; Retry is not covered, and the stream
  state machines are only checked by three specs that kill few mutants.
- **Replay runs real code:** use a scratch clone. On Linux, replay needs
  bubblewrap; the LLVM replay needs the sanitizer runtime
  (`libclang-rt-18-dev`).
- **Note on v0.1.2:** its tag points at an older commit than its date
  suggests, so the pull-request list for this release starts earlier than
  one week ago.
